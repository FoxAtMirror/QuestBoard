# Дорожная карта QuestBoard

Замысел: «вшить» журнал задач в монитор так, чтобы он жил рядом с рабочим столом и
работал как игровой трекер — но настоящие задачи, настоящие дедлайны.

Ниже — развитие идеи от текущего состояния (локальный журнал) к полноценному продукту.

## Уже сделано (v0.1)

- Прозрачное окно-оверлей, всегда поверх окон, привязка к правому краю экрана.
- Поведение «игрового UI», а не окна: без кнопки на панели задач и Alt+Tab, без перехвата фокуса,
  поверх полноэкранных игр (`screen-saver`), два слоя (оверлей / слой рабочего стола).
- Глобальные хоткеи `Ctrl+Alt+Q` и `Ctrl+Alt+N`.
- Журнал квестов: вкладки, цели, награды, дедлайны, важность, зоны-проекты.
- Локальное создание/редактирование/завершение квестов.
- Опыт, уровни героя, звуки, трекер активных квестов.
- Три режима фона, сквозные клики, ресайз, трей, автозапуск с системой.

## Ближайшие шаги (v0.2–v0.3)

1. **Повторяющиеся квесты** — «ежедневные задания»: шаблоны, которые пересоздаются каждое утро.
2. **Дедлайны с напоминаниями** — системные уведомления за N минут до срока, подсветка «просрочено».
3. **Горячие клавиши** — базовые уже есть (`Ctrl+Alt+Q` / `Ctrl+Alt+N`); дальше — настройка сочетаний и
   отдельные хоткеи на «отметить цель выполненной».
4. **Импорт из Markdown/CSV** — чтобы завести существующий список задач за пару секунд.
5. **Темы оформления** — не только «классический WoW», но и стили эпох (Классика, Катаклизм, Драфтхур) и минималистичный «тёмный режим».
6. **Автозапуск с системой** (уже есть флаг в настройках — нужно включить пункт в UI).

## Развитие удалённой выдачи (отложено)

Код сервера уже лежит в `src/main/server.ts` и включается флагом `serverEnabled`:

- страница `http://<ip-компьютера>:7788/` — форма «Выдать квест» с мобильной вёрсткой;
- код доступа + QR-код со ссылкой (интерфейс для этого ещё не сделан);
- для выдачи из интернета — туннель (cloudflared / ngrok) или VPN.

Что нужно доделать: кнопка «Поделиться» в приложении, панель с QR, ротация кода,
авто-открытие туннеля, журнал выданных квестов и защита от спама.

## Большая идея: настоящий аддон для WoW

Самое интересное направление. Сейчас приложение рисует журнал сам. Но можно пойти дальше:

1. **Аддон для World of Warcraft** (аддоны WoW работают только под Windows) читает
   `quests-live.json` и рисует настоящий игровой журнал заданий прямо в игре:
   рамка WoW, золотые названия, звуки выдачи/завершения, трекер справа.
2. Приложение остаётся источником правды: квесты заводишь в удобном оверлее (или на телефоне),
   а видишь их уже в игре — настоящий « quest log ».
3. Обратный канал: аддон может отправлять статус целей обратно (галочка в игре → «выполнено» в приложении).

Технически это самый естественный сценарий: аддон умеет читать JSON из
`%APPDATA%\QuestBoard\quests-live.json` (обновление — по таймеру и по событию файла).

## Другие направления

- **Синхронизация** — OneDrive / WebDAV / Syncthing: одна и та же база на домашнем и рабочем ПК.
- **Интеграции** — GitHub Issues, Jira, Linear, Todoist: квест = привязанная задача со своей прогресс-гистограммой.
- **Статистика и серии** — «20 квестов подряд без пропусков» — прогресс-бар достижения, как в игре.
- **Виджеты рабочего стола** — для Windows 11 / macOS: маленький трекер прямо на обоях.
- **Tauri-версия** — лёгкая сборка (5–10 МБ вместо ~120 МБ у Electron), если захочется «родного» ощущения.
- **Совместные квесты** — несколько героев в одном журнале: «гильдия» с распределением задач.
- **Тёмная тема по времени суток** — днём пергамент, ночью тёмный камень с свечением.
- **Звуки и музыка** — короткие темы из «своих» семплов (без ассетов Blizzard).
- **Экспорт** — календарь (.ics), Markdown-чеклист, печать на стену в стиле WoW-постер.

## Технические заметки

- Данные — обычный JSON с атомарной записью: их легко читать извне, синхронизировать и бэкапить.
  Минус — при очень большом числе квестов (тысячи) лучше перейти на SQLite; точка расширения —
  класс `Store` в `src/main/store.ts`, у него уже чистый публичный интерфейс.
- Оверлей держится на прозрачном окне Electron: на Windows это надёжно, на Linux
  композитор может отличаться (Wayland требует `--enable-features=UseOzonePlatform`).
- Иконки рисуются скриптом `scripts/generate-icons.mjs` — бинарных ассетов в репозитории нет.
